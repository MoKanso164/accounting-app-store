The goal

A shop system that is fast at the counter and honest about the numbers

The store needed quick checkout with a barcode scanner, accurate stock, receipts that print on a thermal printer, and clear daily numbers — in Arabic, on a touch screen. I designed the workflow, the interface and the database, and wired it to the real hardware.

  1. Step 1

    Scan

    The cashier scans a barcode (or taps a product). The item lands in the cart, the price shows on the customer display.

  2. Step 2

    Sell

    Adjust quantities, remove one line, apply a cash discount, then one big button completes the sale and prints the receipt.

  3. Step 3

    Know

    Stock updates instantly. The owner sees sales, profit and low-stock items on the dashboard, reports and charts.

Features

Everything a small shop needs, nothing it doesn’t

Scan & sell

Keyboard-style barcode scanner support, a tap-to-add product picker, quantity +/−, remove a single line without restarting, and a cash discount per line.

Smart pricing

Cost + expenses (fixed or %) + profit % produce the selling price with the shop’s rounding rules, previewed live while typing.

Inventory

Scan an existing barcode to add stock, low-stock items are highlighted, and the stock value is shown at cost and at retail price.

Returns & exchanges

Scan the receipt, return part of a line, or exchange an item — the price difference is calculated and stock is corrected automatically.

Reports & PDF

Today, month, year or any date range, live search across all columns, totals for sales, profit and expenses, and one-click Arabic PDF export.

Charts

Daily, weekly, monthly and yearly sales drawn by a custom chart control — no charting library.

Roles

Admin and seller accounts. Sellers get a lean interface and never see cost price or profit.

Safe test mode

The new version works on a copy of the shop’s database, so it can be tested thoroughly without risking real sales data.

Hardware integration

Built for the real counter, not just the screen

The software talks to the devices on the shop’s checkout: a barcode scanner, an 80 mm thermal printer and a customer-facing display.

80 mm thermal printer

Receipts that look right on paper

The receipt is drawn in code, right-to-left, and sized to the printer’s real printable width so nothing is cut at the edge.

  • Long Arabic product names wrap instead of being truncated
  • Per-line discounts and the grand total
  • A Code 128 barcode of the invoice number — scan the receipt later to start a return
  • Printing runs in the background so the cashier never waits

Customer LED display

The price appears the moment you scan

A serial (COM) driver for the small red 7-segment display facing the customer.

  • Scan → shows the item price, then the running total
  • After the sale → shows the amount paid, then resets to 0.00
  • Selectable command sets, speed and digit count, with a built-in test button

Optional second screen

A full customer display on any monitor

If the checkout has a second monitor, the app opens a customer screen on it automatically — without ever stealing keyboard focus from the scanner. Everything is drawn in code and scales to any screen size.

Oversell-proof checkout

Stock is checked and decremented with one conditional UPDATE … WHERE quantity ≥ n inside the same transaction as the invoice, so two sales can never take the last item.

All-or-nothing operations

Sales, returns and exchanges run as transactions: if any step fails, nothing is written and stock stays correct.

Collision-safe invoice numbers

Readable timestamp-based IDs with an automatic suffix if two sales land in the same second.

Backwards-compatible data

The new C# version reuses the exact five-table schema of the previous Java version, so existing shop data moves across without a migration.

Custom UI toolkit

Rounded buttons, cards, KPI tiles, a vector icon set and a bar-chart control — all drawn with GDI+, no third-party UI kit.

Made for the counter

Responsive layouts for small touch screens, keyboard shortcuts (F1–F4, Ctrl+Enter), and number fields that accept Arabic-Indic digits.
